# Domain docs

## Layout

Use one root `CONTEXT.md` and root `docs/adr/` directory.

## Before exploring

Read `CONTEXT.md` and ADRs relevant to the work.
If they do not exist, proceed without creating placeholders.
Create domain documentation when terms or decisions are resolved.

## Vocabulary and decisions

Use the terms defined in `CONTEXT.md`.
Flag conflicts with an existing ADR explicitly rather than
silently overriding its decision.
